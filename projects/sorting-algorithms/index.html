The project

What I built

Implemented bubble, insertion, selection, quick and radix sorting, with visual explanations and benchmarking.

Why it matters

Two methods can produce the same answer while taking very different amounts of work. Correctness and measurement help make that trade-off visible.

How it works

  1. 01

    Give each algorithm the same five seeded input samples at each size.

  2. 02

    Time the sorting operation, then verify its output against Python’s sorted result.

  3. 03

    Compare median runtimes across five sizes; preserve historical results separately.

What it demonstrates

Algorithmic thinking, regression testing, reproducible experimentation and interpreting performance evidence.

Evidence, with context.

Verified in this review

Four regression test methods pass, covering empty inputs, duplicates, negative values for comparison sorts, random cases and radix-domain validation. The new benchmark verified 125 individual sorts.

Scope and limitations

Timings depend on Python, machine load and hardware. Only random non-negative integers and sizes up to 1,000 were measured here. Quicksort’s worst-case recursion and other input distributions need separate investigation.

Under the surface.

Architecture, methods and improvements

benchmark_verified.py uses random.Random(40), time.perf_counter and median timing. Copies are prepared outside the timed region. The new CSV is separate from historical coursework data, whose aggregation needs further review before making performance claims.

Try it locally

Run python -m unittest test_algorithms.py, then python benchmark_verified.py. Review verified_timings.csv for the new measurements.
